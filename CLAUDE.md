# Hot Boy & Cool Girl

Online 2-player co-op puzzle platformer for phone browsers (TypeScript + Vite + PixiJS v8 + PeerJS, deployed to GitHub Pages).

## Read first

- Never implement something that breaks a design pillar or hard limit in that doc. If a request conflicts with it, point that out first.

## Code notes
- Keep `src/game/` free of TypeScript-only runtime syntax (no parameter properties or enums), so Node can run it directly for `tools/` checks.
- Chapter themes (doc 9.3): each chapter's background colors and scenery are in `src/render/themes.ts`, drawn by `src/render/world.ts`. A level gets its chapter's look through `LevelData.theme` (set by `levelData()`); homemade levels use Chapter 1's. Scenery stays dark and muted and never uses the gameplay colors. Each chapter's tune is in `TUNES` in `src/engine/music.ts` (the stage calls `music.setChapter()`); gem and stone notes follow the playing tune's scale.
- Main menu (doc 11.1, 11.2): screens `home` (main screen with the mode tiles), `coop` (name, create/join) and `settings` in `src/online/game.ts`. Behind them `src/render/title.ts` draws the characters big with a portrait light filter, over the furthest chapter's blurred background; the stage is hidden meanwhile (`Stage.setVisible`). A `?room=` link goes straight to `coop` and joins; leaving a room returns to `coop`. New screens need a `BACK` entry (Android back button).
- New Feel Lab settings go in the `DEFS` list in `src/game/settings.ts`; the panel builds itself from it.
- Official levels: Chapter 1 is in `src/game/levels.ts`, Chapters 2–13 in `src/game/chapterN.ts`; register a new chapter in `CHAPTERS`. Draw a chapter for the doc with `python tools/level_sheet.py <n> docs/levels/chapter<n>.png`.
- Different eyes (doc 16.7): a level's optional `seen` overlay map (`h`/`c` = only Hot Boy / only Cool Girl sees that cell) plus `seen` on a mechanism. Hidden things stay real in physics and in `tools/sim.ts`; only drawing and sound change. `Stage.setViewer()` picks whose eyes a phone sees with (null = everything, as in the Feel Lab and designer).
- Carvings (doc 16.7 G9, changed 2026-11-14): from far away a blank plaque; the animal and dots are drawn only while someone is near (`drawMechs()` in `stage.ts`). In 10-level password chapters they sit off the main path in 4 of levels 1–9 (H2); Chapter 6's are in 6-1, 6-4, 6-6 and 6-8; Chapter 7's in 7-1, 7-4, 7-6 and 7-8, Chapter 9's in 9-1, 9-3, 9-6 and 9-8 (in 7-6, 7-8, 9-3 and 9-6 the one who sees it is not the one who goes to it).
- Password gates (doc 16.7): `stone` and `carving` mechanisms plus a level `pattern` (in `mechanisms.ts`). Official password levels set `teamCode` (the chapter number): carvings take the team code's animal for their dots, and the pattern becomes the code (`withCode()` in `levels.ts`). Team codes live in `src/game/teamCode.ts`; the host settles them in the room. The route robot plays them with `TEST_CODE` (`tools/routes.ts`), and the vaults (6-10, 7-10, 9-10, 13-5) also with many codes via `CODE_ROUTES`. Chapter 7 (doc 16.10) mixes both: carvings and vault stones with `seen`. Symbol stones go on their own shelves (doc 16.1).
- Don't touch (doc 16.7, T1–T4; Chapter 8, 9-2…9-4 and 9-10): a level sets `apart`; `touching()` in `src/game/body.ts` is the clear-overlap test for the game and `tools/sim.ts`. Online, each phone reports its own sighting with a `touch` message and bursts only when both phones saw one (`localTouch` hook in `src/play/stage.ts`, handled in `src/online/game.ts`). The level designer doesn't have it yet (T4).
- 10-level chapters (doc 16.7, "The road to 100 levels"): a planned level is a `LevelDef` with `rows: null` (shown as "soon"). `BUILT_LEVELS` in `levels.ts` is what the unlock chain and "Next level" walk; `isUnlocked()` in `progress.ts` also opens a level when it or any later one is finished (old saves keep everything). The vaults are 6-10, 7-10 and 9-10 (they were 6-5, 7-5, 9-5; `progress.ts` moves old saved results once per phone). Ids of existing levels never change otherwise.
- The Trials (doc 16.7): three very hard bonus chapters (10–12) behind the "Bonus levels" tile; D2 and D11 are relaxed there. A bonus chapter has `bonus: true` in `CHAPTERS` (`STORY_CHAPTERS`, `BONUS_CHAPTERS` and `FINALE_ID` in `levels.ts`): the story still counts 9 chapters, "Next level" stops at 9-5 and the ending stays on 9-5. All three mechanics are built. Chapter 10 "The Crumbling Wing" (doc 16.13) Chapters 11 and 12 (doc 16.14, 16.15) have 10 levels each, and Chapter 13 "The Last Trial" (doc 16.16) has 5 with every mechanic, its own team code and a vault (13-5) above the tide. The game has 100 levels. The plan to 100 levels (10 levels in Chapters 6–12, a new Chapter 13, hidden carvings) is in doc 16.7 "The road to 100 levels" (H1–H5), with the order of work.
- Crumbling stones (doc 16.7, K1–K6): a `crumble` mechanism (a row of one-tile blocks) in `mechanisms.ts`: shakes 0.7 s when stood on, falls, grows back 5 s later, never inside a character. Online, the stepper's phone sends a `crumble` message and the host's world state carries every block's clock (`cr`). Official levels only for now (the level designer can't place or share them).
- Timed switches (doc 16.7, S1–S6): a `timer` mechanism (on while stood on, then `secs` more seconds) in `mechanisms.ts`; `runeClock()` draws the draining ring on what it powers. The host's world state carries the clocks (`tm`). A level that uses one writes its route in `tools/routes.ts` as a function (`() => Route`): the robot plays it twice, the second time with every clock 0.5 s shorter (room for lag). Official levels only for now.
- The rising tide (doc 16.7, V1–V6): a level sets `tide: { from, to, speed }`; the state is `mech.tide` (starts on the first move, kills 0.3 tiles under the surface, `td` in the host's world state). Drawn by `drawTide()` in `stage.ts`. A tide level keeps both bottom 4 × 4 corners solid, and its route is a function too: the robot replays it with the tide 1.25× faster.
- Feel Lab test rooms: `?lab=vault` (stones and carvings), `?lab=crumble` (crumbling stones), `?lab=timer` (timed switches), `?lab=tide` (the rising tide), `?lab=<level id>` (any official level, with a random team code).
- Solo test (`?solo`, `?solo=<level id>`, `src/lab/soloTest.ts`; in the test APK from the Settings button): the owner plays every official level alone with real rules (death restarts, both in doors wins), a level list with ✓ marks, swap, whose-eyes toggle, one random code per password chapter per visit. Never records progress or stars. Its Settings button shows in dev or after `?solo` was opened once on that device.
- Selling (doc 12.6): free/paid rules, `PAYWALL_LIVE` and the product ID are in `src/game/unlock.ts`; the Google Play purchase is `src/shop/billing.ts` (only active in the app). Player sound/vibration choices: `src/game/prefs.ts`. Friends must share the same play version (`src/game/version.ts`): bump `PROTOCOL` when the messages between phones change.
- Links and store asks (docs/MARKETING_PLAN.md): `src/game/links.ts` has the website address (`WEB_URL`; every shared link uses it, since the app's own address is `https://localhost/`), the store link with a `utm_source` tag, and `SUPPORT_EMAIL` (empty = no feedback link). `src/shop/review.ts` asks Google Play for a rating after a chapter's last level (app only, at most once a month). The link preview is in `index.html` with `public/share-card.jpg`; the about/press page is `public/about.html` with images in `public/press/` (both made by `tools/store_assets.py`).
- Android app (Capacitor, `android/`): `npm run app:sync` builds the game into `dist-app/` and copies it in; release steps are in `docs/RELEASE_ANDROID.md`. Every push to `main` also builds a test APK on GitHub (`.github/workflows/android-apk.yml`) onto the fixed `apk` release, signed with the `ANDROID_TEST_KEYSTORE` secret. Store images: `python tools/store_assets.py docs/store/raw docs/store`.
- Level designer (doc 16.3): a homemade level's ✅ is set **only** in `verifyTogether()` in `src/online/game.ts` (an online 2-player finish). Never add another path that verifies.

## Commands
- `npm run dev`: HTTPS dev server reachable from phones on the LAN (`https://<PC-IP>:5173/hot-boy-cool-girl/`)
- `npm run dev:http`: plain HTTP on :5174 for desktop-only testing
- `npm run build`: typecheck and production build
- `npm run check:metrics`: movement vs. level metrics (run after changing movement defaults in `src/game/settings.ts`)
- `npm run check:custom`: level designer data (share links, fingerprint, level checker; every official level must pass the checker)
- `npm run check:routes`: plays every official level with its written solution in `tools/routes.ts` using the real physics (`tools/sim.ts`). A new or changed level needs a solution that passes (doc 16.1 D13). `npm run check:routes -- 2-3 -v` traces one level
- `npm run check:unique`: compares every pair of official levels, as built and mirrored (doc 16.1 D14); fails when two rooms share 80% or more. `-- -v` lists the closest pairs, `-- --all` each level's closest other level
- Pushing to `main` deploys to https://mohammad-ayeshh.github.io/hot-boy-cool-girl/
